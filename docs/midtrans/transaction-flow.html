5

Cek Pending Order (Anti Double-Charge)

Sebelum checkout, frontend memanggil GET /api/account/pending-order. Jika ada order checkout_created sebelumnya: (a) jika status Midtrans sudah terminal (expire/cancel/deny) → server auto-cancel order, lanjut checkout; (b) jika masih aktif → tampilkan dialog "Resume Payment" atau "Cancel". Customer tidak bisa checkout baru sampai pending order diselesaikan.

API: GET /api/account/pending-order → cek billing_orders status checkout_created | Midtrans status check: GET /v2/{order_id}/status

6

Server WebWeave Membuat Invoice Midtrans

Frontend mengirim POST /api/billing/checkout dengan body { plan, billingCycle } (email customer diambil dari session Supabase, bukan input manual). Server generate order_id unik (format: ww_{12charUserIdPrefix}_{10charSha256Hash}), lalu memanggil Midtrans Invoice API POST /v1/invoices dengan: item_details (nama paket, harga), customer_details (email dari session), payment_type = payment_link. Midtrans merespons dengan payment_link_url. Order disimpan di Supabase billing_orders dengan status checkout_created.

API: POST /api/billing/checkout → src/lib/billing/midtrans.js (createInvoice) | Email: auth.user.email dari Supabase session

Midtrans Mengirim Webhook Notifikasi ke WebWeave

Midtrans mengirim HTTP POST notification ke endpoint webhook WebWeave. Server memverifikasi signature_key dengan SHA-512 hash (gabungan order_id + status_code + gross_amount + ServerKey). Jika valid dan status = settlement atau capture, akun customer otomatis di-upgrade.

Auto-refresh: visibilitychange event → loadPrivateData() | Kuota: usage_events table (monthly tracking)

6. Catatan Teknis untuk Midtrans

  • Tipe integrasi: Invoice API (bukan Snap popup, bukan Core API direct charge).
  • Environment: Saat ini menggunakan Midtrans Sandbox untuk testing. Production key akan digunakan setelah aktivasi.
  • Webhook URL (production): https://web-weave-lake.vercel.app/api/billing/midtrans/webhook
  • Webhook retry: WebWeave return HTTP 200 setelah berhasil verifikasi & update. Jika gagal, return non-200 → Midtrans retry.
  • Anti double-charge: Sebelum checkout, frontend cek pending order via GET /api/account/pending-order — jika ada order checkout_created aktif, customer harus resume/cancel dulu. Setelah webhook settlement, server auto-cancel order checkout_created lain milik user yang sama.
  • Order ID format: ww_{12charUserIdPrefix}_{10charSha256Hash} — hash dari planId + billingCycle + timestamp + random bytes. Contoh: ww_a1b2c3d4e5f6_f8k2lm9p0q
  • Tidak ada Snap popup: WebWeave menggunakan Invoice API yang menghasilkan payment link. Customer redirect ke halaman Midtrans, bukan popup di website WebWeave.
  • Data pembayaran: WebWeave TIDAK menyimpan, memproses, atau mengakses data kartu/debit. 100% diproses Midtrans.
  • Refund: WebWeave yang menginisiasi refund via dashboard Midtrans jika memenuhi syarat (double charge / downtime >72h). Tidak ada auto-refund.
