C. End-to-End Process Customer (Dari Pesan Sampai Pembayaran)

WebWeave adalah layanan SaaS self-service. 100% transaksi digital — tidak ada pengiriman barang fisik, tidak ada jadwal pengiriman, tidak ada logistik.

Langkah 1 — Registrasi & Login

  • Customer mengakses WebWeave melalui browser.
  • Registrasi/login menggunakan Google OAuth (via Supabase Auth).
  • Akun default masuk paket Free (5 generasi/bulan, 1 project).

Langkah 2 — Pemilihan Paket

  • Dari halaman utama, customer klik tombol Upgrade atau menu Pricing.
  • Modal pricing menampilkan pilihan paket Starter dan Pro.
  • Customer memilih paket dan siklus billing (monthly/annual).
  • Tombol "Pay Now" / "Complete Payment" mengarah ke checkout.
  • Sistem memvalidasi: (a) customer terautentikasi, (b) paket yang dipilih lebih tinggi dari paket saat ini, (c) origin request valid (anti-CSRF).

Langkah 3 — Checkout ke Midtrans

  • Server WebWeave memanggil Midtrans Invoice API (POST /v1/invoices) — BUKAN Snap popup.
  • Midtrans membuat invoice dengan: order_id unik, detail item (paket), detail customer (email), payment_type = payment_link.
  • Midtrans merespons dengan payment_link_url dan pdf_url.
  • Order disimpan di database Supabase (billing_orders) dengan status checkout_created.
  • Customer diarahkan ke payment_link_url milik Midtrans.

Langkah 4 — Pembayaran di Midtrans

  • Customer memilih metode pembayaran di halaman Midtrans (transfer bank, QRIS, e-wallet, dll).
  • Customer menyelesaikan pembayaran sesuai instruksi Midtrans.
  • Seluruh data kartu/pembayaran diproses SEPENUHNYA oleh Midtrans. WebWeave tidak menyimpan data pembayaran apapun.

Langkah 5 — Verifikasi & Aktivasi Layanan

  • Midtrans mengirim webhook notifikasi ke endpoint WebWeave: POST /api/billing/midtrans/webhook.
  • Server WebWeave memverifikasi signature_key notifikasi dengan SHA-512 hash.
  • Status settlement / capture → akun customer otomatis upgrade ke paket yang dibeli.
  • Kuota generasi bulanan, slot project, dan slot script langsung aktif.
  • Status non-terminal (pending) tidak mengubah akun.
  • Status terminal inaktif (expire, cancel, deny) tidak meng-upgrade akun.
  • Untuk local dev/testing: status dicek manual via GET /api/billing/midtrans/status?order_id=xxx.

Langkah 6 — Penggunaan Layanan

  • Customer langsung menggunakan layanan WebWeave: memasukkan URL target + objective, menghasilkan script automation dengan AI.
  • Kuota monthly berlaku 30 hari (monthly) atau 365 hari (annual).
  • Masa aktif kedaluwarsa: akun kembali ke paket Free otomatis.
  • Customer dapat upgrade kapan saja, dicegah membeli paket yang sama/lebih rendah (menghindari double billing).

F. Keamanan & Kepatuhan

  • Server-side checkout — tidak ada API key Midtrans yang terekspos ke browser.
  • Verifikasi signature SHA-512 pada setiap webhook notifikasi.
  • Validasi origin request untuk mencegah CSRF pada endpoint checkout.
  • Supabase Row Level Security (RLS) memastikan data pengguna hanya diakses oleh pemiliknya.
  • Semua komunikasi via HTTPS (Vercel hosting).
  • WebWeave TIDAK menyimpan, memproses, atau mengakses data kartu kredit/debit. Seluruh pemrosesan pembayaran dilakukan oleh Midtrans.
  • Order ID digenerate menggunakan kombinasi user prefix + SHA-256 hash + timestamp untuk mencegah tabrakan.
  • Privacy Policy & Terms of Service tersedia di /privacy dan /terms.
